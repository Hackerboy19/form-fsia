fsia.in: speed, sitemap, SEO and security

73 registration-form pages in form-fsia 5,519 live sitemap URLs crawled Real-browser tests on 6 pages

TL;DR

  • Fast

    The server is fast. PHP pages are generated in about 0.02–0.2 s. Speed problems are in what the browser has to download and run.

  • Slow

    Nothing is cached. CSS, JS and images are all sent with no-store, and Tailwind compiles in the browser on every page. Forms take 1.7–2.8 s to show anything. The homepage's largest element appears at 4.1 s, which Google rates "poor".

  • Sitemap

    59 live pages are missing from the sitemap, including 51 of 64 state Miss/Mrs forms. 192 sitemap URLs are broken: 80 return 404 and 76 return a 500 server error.

  • SEO

    Bharat Couture Week points Google to a page that redirects to the homepage. Google will likely drop it. Also: 49 titles are too long, 13 pages have two H1s, and 71 pages describe a year-long fake "Event".

  • Security

    Any state page can send a WhatsApp OTP to any number via ?action=send_otp, with no rate limit. The OTP uses weak randomness, wrong guesses are unlimited, there is no CSRF protection, and a webhook ID is committed to git.

  • Code

    The 73 form files are about 95% identical. Every fix has to be made 64–73 times. Header, footer, config and save scripts are not in the repo.

Performance

What's fast and what's slow

Fast Working well

  • PHP generation takes ~20–200 ms. A static robots.txt has nearly the same TTFB (0.77 s) as a form page (0.79–0.98 s).
  • TTFB is steady across 5,325 working URLs: p50 0.84 s, p99 1.06 s.
  • HTTP/2, gzip on HTML and Brotli on CSS/JS are all on.
  • Form pages barely shift while loading (CLS ≤ 0.01) and transfer about 85 KB.
  • http, non-www and trailing-slash URLs 301 correctly. Unknown URLs return a real 404.

Slow Why pages feel slow

  • no-store on every file, so assets are re-downloaded on every view.
  • A PHP session cookie is set for every anonymous visitor, so no CDN can cache the HTML.
  • The Tailwind CDN script (126 KB) builds CSS before the first paint.
  • 6 stylesheets block rendering: 2 from Google Fonts and 4 from the site.
  • calendar.js and promo.js are the slowest requests (1–2 s) on every form.
  • About 95 KB of inline CSS and JS is repeated in every page, so it can't be cached.
  • TLS handshake takes about 0.5 s from outside India; a CDN would fix this.

  • Remove the inline OTP handler, switch to random_int, rate-limit, turn TLS checks on, rotate the webhook ID
  • Fix the Bharat Couture canonical, add the 59 missing pages, remove the 192 broken URLs, resubmit in Search Console
  • Set cache headers on static files and stop starting sessions on anonymous page views
Week 2
  • Build Tailwind CSS, merge the stylesheets, defer JS, preconnect fonts, load calendar/promo later
  • Titles ≤ 60 characters, descriptions ≤ 155, one H1 per page, fix the Event schema
Week 3
  • Single form template, shared PHP in git, CSRF tokens
  • Database-generated sitemap and one consistent URL style with 301s
Week 4
  • Homepage images: WebP, dimensions, alt text. Put the site behind a CDN.
